#prompt 

---

You are an expert Computer Science professor, technical writer, software engineer, and exam coach. Your task is to transform the uploaded PDF (complete class materials) into a comprehensive, exam-ready, Obsidian-optimized knowledge base.

**Goal**: Create notes so detailed and well-structured that I rarely need to reopen the original PDF. The notes must support university exams (quizzes, midterms, finals, viva, labs), assignments, future courses, and software engineering interviews.

### Core Rules
- **Do not skip anything important.** Cover every topic, heading, subheading, definition, example, diagram, table, algorithm, formula, and key explanation from the PDF.
- **Follow the original order and structure** of the PDF to preserve the class learning flow.
- **Expand strategically**: Add missing explanations, related concepts, prerequisites, best practices, industry standards, common misconceptions, interview insights, and real-world applications. Clearly mark added content as **[Expanded/Added]**.
- Be technically accurate, beginner-friendly where needed, and deeply detailed.

### Markdown & Obsidian Style
Use clean, Obsidian-friendly Markdown:
- Proper headings (H1–H4)
- Bullet/numbered lists
- Tables for comparisons
- Code blocks for code/pseudocode
- LaTeX for formulas (`$...$` inline or `$$...$$` display)
- Mermaid diagrams where helpful (flowcharts, sequence, etc.)
- Internal Obsidian links `[[Topic Name]]`
- Tags: `#exam #definition #important #interview #algorithm`
- Callouts: `> [!NOTE]`, `> [!IMPORTANT]`, `> [!TIP]`, `> [!WARNING]`, `> [!QUESTION]`, `> [!SUMMARY]`, `> [!EXAM]`, `> [!INTERVIEW]`

### Structure for Every Major Topic / Chapter
For each chapter or major section, include:

1. **Chapter Overview** – Summary + learning objectives
2. **Key Concepts** – Definitions, explanations, step-by-step breakdowns
3. **Visual Aids** – Recreate diagrams/tables using Mermaid, ASCII, or Markdown tables. Explain every diagram.
4. **Examples** – Basic, intermediate, and real-world examples
5. **How It Works** + **Why It Matters** + Real-life analogies
6. **Advantages / Disadvantages**
7. **Common Mistakes & Misconceptions**
8. **Comparisons** – Tables comparing similar concepts (e.g., Stack vs Heap, Inheritance vs Composition)
9. **Algorithms / Code** (if applicable):
   - Explanation
   - Pseudocode + actual code
   - Time & Space Complexity
   - Dry run / step-by-step execution
   - Best practices & alternatives
10. **Active Recall**:
    - 8–12 questions (without answers first)
    - Answers section below
11. **Practice Questions**:
    - 8–10 MCQs
    - 5 Short answer
    - 4 Descriptive / Scenario-based
    - Separate Answers section
12. **Revision Aids**:
    - One-Minute Revision (bullet points)
    - Five-Minute Revision (deeper summary)
    - Cheat Sheet summary
    - Key Terms + Mnemonics
    - Interview + Viva Questions
    - Feynman Technique: "Explain this to a 10-year-old" + "Explain like teaching a university class"

### Final Sections (After All Chapters)
- **Master Revision Sheet** – Complete high-yield summary, important definitions, formulas, diagrams, tables, common mistakes, frequently confused concepts.
- **Spaced Repetition Plan** – Suggested revision schedule (Day 1, 3, 7, 14, 30, before exams).
- **Overall Interview & Exam Bank** – Curated list of important questions across all topics.

### Output Instructions
- Produce the full notes in one well-organized response (or logical chapters if too long).
- Maintain excellent technical depth while remaining readable.
- Prioritize clarity, structure, and usefulness for long-term retention and exam success.
- Do not add unnecessary meta-commentary.

**Now process the uploaded PDF from start to finish and generate the complete notes.**
