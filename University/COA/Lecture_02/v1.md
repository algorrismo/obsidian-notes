## 1. Theory Notes

### 1.1 Positional Number Systems

In a positional system with base $b$, each digit's value depends on its position (power of $b$). Symbols range from $0$ to $b-1$.

$$N = \sum_{i} d_i \times b^i$$

|System|Base|Digits Used|
|---|---|---|
|Decimal|10|0–9|
|Binary|2|0,1|
|Hexadecimal|16|0–9, A–F (A=10 … F=15)|

> [!tip] Why Hexadecimal? Binary is long/hard to read (16 bits per word on 8086). Decimal is hard to convert to binary. Since $16 = 2^4$, **each hex digit = exactly 4 bits**, making hex↔binary conversion trivial. This is why hex exists as a "shorthand" for binary.

**Example — Decimal:** $3245 = 3{\times}10^3+2{\times}10^2+4{\times}10^1+5{\times}10^0$ **Example — Binary:** $11010_2 = 1{\times}2^4+1{\times}2^3+0{\times}2^2+1{\times}2^1+0{\times}2^0 = 26_{10}$ **Example — Hex:** $4A_{16} = 4{\times}16^1+10{\times}16^0 = 74_{10}$

### 1.2 Conversion Methods

|Conversion|Method|
|---|---|
|Decimal → Binary/Hex|Repeated division by base; collect remainders **bottom-to-top** (last remainder = MSB)|
|Binary/Hex → Decimal|Multiply each digit by base raised to its position power, sum all|
|Hex ↔ Binary|Each hex digit ↔ exactly **4 binary bits** (direct lookup, no division needed)|

> [!note] Direction matters! Decimal→other base: **divide**, read remainders bottom-up. Other base→Decimal: **multiply & sum** using positional weights.

### 1.3 Hex / Binary Addition & Subtraction

- **Addition:** Add column by column (right→left). If sum ≥ base, write `sum − base`, carry 1.
- **Subtraction:** Subtract column by column. If minuend digit < subtrahend digit, **borrow** `base` from the next column (i.e., add base to current digit, subtract 1 from next column before subtracting).
- For binary, pad the shorter number with leading zeros to match bit-length before operating.

### 1.4 Integer Representation in Computers

- **lsb** = least significant bit = rightmost bit (bit 0)
- **msb** = most significant bit = leftmost bit (bit 15 in a 16-bit word, bit 7 in a byte)
- Hardware fixes a word's size (e.g., 8 bits = byte, 16 bits = word), which **limits the range** of representable numbers.

**Unsigned integers** (non-negative only):

|Width|Max value (binary)|Max (dec)|Max (hex)|
|---|---|---|---|
|Byte (8-bit)|`11111111`|255|FFh|
|Word (16-bit)|`1111111111111111`|65535|FFFFh|

> [!tip] Odd/Even shortcut If **LSB = 1** → number is **odd**. If **LSB = 0** → number is **even**.

**Signed integers** (positive or negative):

- **MSB reserved as sign bit**: `MSB = 0` → positive, `MSB = 1` → negative.
- Negative numbers are stored using **Two's Complement**.

**One's Complement:** invert every bit (0→1, 1→0). **Two's Complement:** one's complement **+ 1**.

$$\text{Two's Complement}(N) = \overline{N} + 1$$

> [!note] Key property Adding $N$ + (Two's complement of $N$) gives all zeros (the extra carry-out bit is discarded since it exceeds the fixed word size) — this is exactly how $N + (-N) = 0$. Adding $N$ + (One's complement of $N$) gives **all 1's**. Taking the two's complement **twice** returns the original number.

**Subtraction via addition:** $A - B = A + \text{Two's Complement}(B)$ (discard any overflow carry out of the word width).

**Range for $n$-bit signed (two's complement) numbers:** $$-2^{n-1} ;\text{to}; 2^{n-1}-1$$

- 8-bit signed range: **−128 to 127**
- 16-bit signed range: **−32768 to 32767**

> [!warning] Overflow A value outside this range **cannot** be correctly represented in that word size — e.g., −40000 or 65536 overflow a 16-bit signed word.

### 1.5 ASCII Code

- ASCII uses **7 bits** → $2^7 = 128$ possible codes (characters 0–127).
- Codes **32–126** (95 codes) are **printable** characters; codes below 32 (and 127) are control characters.
- Each character is stored as **1 byte** in memory at a sequential address.
- Example: to display `A` on screen, the program sends ASCII code `41h` (decimal 65).

## 2. Worked Examples

### Example 1 — Decimal → Binary

Convert $25_{10}$ to binary.

```
2 | 25
2 | 12 → remainder 1
2 |  6 → remainder 0
2 |  3 → remainder 0
2 |  1 → remainder 1
2 |  0 → remainder 1
Read remainders bottom→top: 11001₂
```

**Answer: $25_{10} = 11001_2$**

### Example 2 — Decimal → Hex

Convert $415_{10}$ to hex.

```
16 | 415
16 |  25 → remainder F (15)
16 |   1 → remainder 9
        0 → remainder 1
Read bottom→top: 19F₁₆
```

**Answer: $415_{10} = 19F_{16}$**

### Example 3 — Hex → Decimal

Convert $589_{16}$ to decimal. $$589_{16} = 5{\times}16^2 + 8{\times}16^1 + 9{\times}16^0 = 1280+128+9 = 1417_{10}$$

### Example 4 — Hex → Binary (direct nibble mapping)

Convert $39A2_{16}$ to binary.

|Hex|3|9|A|2|
|---|---|---|---|---|
|Binary|0011|1001|1010|0010|

**Answer: `0011 1001 1010 0010`**

### Example 5 — Hex Addition

Add $5B39_{16} + 7AF4_{16}$.

```
  5B39
+ 7AF4
------
Units: 9+4 = 13 = D
Next:  3+F = 12h, write 2 carry 1
Next:  B+A+1 = 16h, write 6 carry 1
Next:  5+7+1 = D
------
  D62D
```

**Answer: $D62D_{16}$**

### Example 6 — Hex Subtraction (with borrow)

Subtract $BA94_{16}$ from $D26F_{16}$.

```
Units: F − 4 = B
Next : 6 < 9 → borrow: (16+6) − 9 = D
Next : (2−1) − A = needs borrow: (16+1) − A = 7
Next : (D−1) − B = 1
------
  17DB₁₆
```

**Answer: $17DB_{16}$**

### Example 7 — Two's Complement of 5 (16-bit)

```
5 = 0000000000000101
One's complement: 1111111111111010
        +1
Two's complement: 1111111111111011
```

**Verification:** $0000000000000101 + 1111111111111011 = 1,0000000000000000$ → the leading carry bit is discarded (word = 16 bits) → result = `0000000000000000` = 0. ✓ ($5 + (-5) = 0$)

### Example 8 — Subtraction via Two's Complement Addition

If `AX = 21FCh` and `BX = 5ABCh`, find `AX − BX`.

```
AX = 21FCh = 0010000111111100
BX = 5ABCh = 0101101010111100

One's complement of BX:  1010010101000011
                        +1
Two's complement of BX:  1010010101000100 = A544h

AX + (Two's complement of BX) = 21FCh + A544h = C740h
```

**Answer: AX − BX = C740h**

### Example 9 — 16-bit Two's Complement Representation

Represent $-32216$ in 16-bit hex.

```
32216 (unsigned) → binary: 0111110111011000 = 7DD8h
Invert: 1000001000100111
   +1 : 1000001000101000 = 8228h
```

**Answer: $-32216 \rightarrow 8228h$** _(Shortcut check: $2^{16} - 32216 = 65536 - 32216 = 33320 = 8228h$ ✓)_

### Example 10 — String Storage (ASCII)

Store the string `"Hello World"` in memory (address 0 onward).

|Address|Char|ASCII (Dec)|ASCII (Hex)|
|---|---|---|---|
|0|H|72|48h|
|1|e|101|65h|
|2|l|108|6Ch|
|3|l|108|6Ch|
|4|o|111|6Fh|
|5|(space)|32|20h|
|6|W|87|57h|
|7|o|111|6Fh|
|8|r|114|72h|
|9|l|108|6Ch|
|10|d|100|64h|

> [!warning] Common Pitfalls
> 
> - Forgetting to **pad with zeros** before binary addition/subtraction when operand lengths differ.
> - Confusing **one's complement** (invert only) with **two's complement** (invert + 1) — only two's complement is used to represent negative numbers in hardware.
> - Forgetting that the **carry-out bit beyond the fixed word size is discarded** — this is what makes $N+(-N)=0$ work.
> - Mixing up MSB/LSB direction — MSB is leftmost (sign bit), LSB is rightmost (odd/even indicator).
> - Assuming any decimal number fits in a given word size — always check the signed range ($-2^{n-1}$ to $2^{n-1}-1$) before converting; values like −40000 or 65536 **overflow** a 16-bit word.

## 5. Practice Questions (with Answers)

**Q1. What is the base of the hexadecimal number system, and how many unique digit symbols does it use?** **A:** Base 16; it uses 16 symbols: 0–9 and A–F.

**Q2. Why is hexadecimal preferred over binary for representing machine words?** **A:** Because binary representations are long and hard to read/write, while hex is compact (1 hex digit = 4 bits) and converts directly to/from binary without arithmetic.

**Q3. Convert $1110_2$ to decimal.** **A:** $14_{10}$ ($8+4+2+0$).

**Q4. Convert $46A_{16}$ to decimal.** **A:** $1130_{10}$ ($4{\times}256+6{\times}16+10$).

**Q5. What does the LSB tell you about a number's parity?** **A:** If LSB = 1, the number is odd; if LSB = 0, the number is even.

**Q6. In signed integer representation, what does the MSB indicate?** **A:** The sign: MSB = 0 means positive, MSB = 1 means negative.

**Q7. How do you compute the two's complement of a binary number?** **A:** Invert every bit (one's complement), then add 1.

**Q8. What is the signed range of an 8-bit two's complement number?** **A:** −128 to 127.

**Q9. Why does adding a number to its two's complement yield zero in a fixed-width register?** **A:** The sum produces a 1 followed by all zeros, one bit wider than the register; the extra leading 1 (carry-out) is discarded because it doesn't fit the fixed word size, leaving all zeros.

**Q10. How many bits does standard ASCII use, and how many characters can it represent?** **A:** 7 bits, representing $2^7 = 128$ characters (codes 0–127).

**Q11. Which ASCII code range contains the printable characters?** **A:** Decimal 32 to 126 (95 printable characters); codes outside this range (0–31, 127) are control characters.

**Q12. Can −40000 be represented in a 16-bit signed (two's complement) word? Why or why not?** **A:** No — the 16-bit signed range is −32768 to 32767, and −40000 falls outside (below) that range, causing overflow.
